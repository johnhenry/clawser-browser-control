PERMISSION JUSTIFICATIONS AND LISTING COPY
==========================================
Copy-paste into the store dashboards; docs/STORES.md says which field takes which block. Each permission is explained in terms of per-site grants and tool classes (read, interact, sensitive). Keep this file in step with manifest.json and firefox/manifest.json: test/packaging.test.mjs fails if a permission has no heading here, or a heading names one the manifest no longer asks for.

How access works (put this in "additional notes" fields):
Every page the extension can touch is a site the person granted, by exact origin (scheme, host and port), in the extension's own options page. A page that asks to be paired cannot grant itself anything. Each granted site also carries tool classes the person ticks there: "read" (see the page), "interact" (act on it) and "sensitive" (screenshots, GIF recording, console and network monitoring). A new grant allows "read" only. On every call the extension checks the site and the class and refuses anything else (site_not_granted, class_not_allowed, capability_disabled).

=== CHROME AND EDGE ===
Used for the Chrome Web Store and Microsoft Edge Add-ons (the same package, manifest.json).

tabs
----
Needed so the extension can list the open tabs and open, navigate and close them. A tab is listed to the paired Clawser page only when its site is granted; the list shows the title and origin, never the full address. Opening, navigating and closing are "interact" tools and only work on a granted site that allows that class.

activeTab
---------
Lets the right-click entries and the side panel work on the tab the person is looking at when they choose one. It adds no access beyond the person's own click; the per-site grant still decides what the paired page may read or do afterwards.

scripting
---------
Needed to run the extension's own page reader and input code in a tab: read the text, structure and form state of the page, and click, type, fill and scroll. Reading is the "read" class and acting is the "interact" class, both checked per site; password, payment and one-time-code fields are returned blank. The extension runs only its own packaged code this way, never code from a web page or a server.

userScripts
-----------
Used only so a person can run a script they wrote themselves in the Clawser workspace on a page. It is off for a paired page until the person turns on the matching per-page switch in the options page, and it is never offered through the viaframe bridge. The scripts are the person's own; none are fetched from a server.

webRequest
----------
Used only to observe request metadata (method, status, type and an address with credentials, query values and fragment removed) on a granted tab that allows the "sensitive" class, while the person has started monitoring. It is observation only: no header, cookie or body is recorded, and nothing is blocked or changed.

cookies
-------
Used only when a person has switched on the cookies capability for one paired page in the options page. It is off by default and is not offered through the viaframe bridge. Cookie values stay on the machine and go only to that paired page.

storage
-------
Keeps the extension's settings on this machine: the paired origins and their tokens, the granted sites and the classes allowed on each, the audit log and the saved browser-task state. Nothing is synced or sent anywhere.

alarms
------
Wakes the extension once a minute to check whether a Clawser routine is due, so a routine can still run when the browser has no Clawser tab open. A routine unattended can reach only the sites its own signed grant names, and no others.

offscreen
---------
Needed only to encode a GIF the person asked to record: a Manifest V3 background worker has no canvas, so frames are encoded in a hidden offscreen document that exists only while encoding and sends nothing anywhere. Recording is a "sensitive" tool: it takes frames only while the shown tab is on a granted site that allows that class, and leaving the site ends it and drops the frames.

sidePanel
---------
Shows the browser-tasks panel next to the page: launchers, a picker for the tabs the person chooses, and their saved tasks and inbox. It only prepares a draft message for the person's own Clawser tab; nothing runs until the person confirms in Clawser.

contextMenus
------------
Adds the right-click entries "Extract data from the selection", "Extract data from this page", "Compare with other tabs" and "Watch the selection". When the person picks one, the extension sends the page title and address, and a selector and a short text hint for a selection, to the person's Clawser tab as a draft. Nothing is read in the background and nothing runs until the person confirms.

debugger (optional)
-------------------
Declared optional and not used by any action in this version. It is never requested today. If a future version uses it, it would be requested at that moment with the person's consent and would be subject to the same per-site grants and "sensitive" class.

<all_urls>
----------
Why a blanket pattern for a per-site product: Chrome and Edge only let an extension inject its page reader into a site if the manifest names that site, and a person chooses which sites at run time, so the manifest cannot list them in advance. The pattern is not the permission to use them. Access is gated in the extension by per-site grants: until a person grants a site's exact origin in the extension's own options page, every call on it is refused with site_not_granted, the tab is not listed, and nothing is read, injected or recorded. Granting a site allows "read" tools only; "interact" and "sensitive" tools are separate ticks per site, and each call is checked against them. The extension keeps an audit log a web page cannot clear. (A planned follow-up moves this to optional host permissions requested per site, so the browser asks as well.)

Single purpose description
--------------------------
This extension lets the Clawser AI agent workspace (running on the person's own machine) work with the person's browser tabs: listing tabs, reading pages, clicking and typing, taking screenshots and watching a page, only on the sites the person grants and only for the tool classes they allow on each site.

FIREFOX SUMMARY: Lets the Clawser agent work in the tabs and sites you grant, one site at a time. You allow read, interact or sensitive tools for each site; everything else is refused.
CATEGORY: Developer Tools (Chrome Web Store); Productivity or Developer Tools (Edge); Other (Firefox)
LANGUAGE: English

DATA USE (Chrome "privacy practices" tab): collects no user data to a server. Certify: not sold, not used for unrelated purposes, not used for creditworthiness.

--- Detailed description (Chrome Web Store, Edge Add-ons) ---
Clawser Browser Control is the companion extension for the Clawser browser agent workspace, a browser-native AI agent runtime that runs on your machine.

You decide, site by site, what Clawser can do:
- Pair a Clawser page in the extension's own options page. A page can ask to be paired; it cannot approve itself.
- Grant a site by its exact origin. A new grant allows "read" tools only, such as seeing the page and listing the tab.
- Tick "interact" (open, navigate, click, type, fill, scroll) or "sensitive" (screenshots, GIF recording, console and network monitoring) for that site only if you want them.
- Everything else is refused, and the extension keeps an audit log that a web page cannot clear.

Also included: a side panel and right-click menu that prepare browser tasks (extract, compare, watch) as drafts in Clawser, and nothing runs until you confirm there.

Privacy: password, payment and one-time-code fields come back blank, network entries carry no credentials or query values, and the extension has no analytics, no telemetry and no server of its own. What it reads goes only to the Clawser page you paired.

Requires Chrome or Edge 135 or later.

--- Notes for the reviewer (Edge "Notes for certification"; AMO "Notes to reviewer") ---
To see what the extension does you need the Clawser workspace, which is a web app: https://clawser.erisera.com, or a local copy on http://localhost. Open the extension's options page (the toolbar button's menu, "Options") and under "Paired pages" press Pair next to the Clawser origin. Under "Granted sites" add a site's exact origin (for example https://example.com); a new grant allows read tools only. Without a grant every call is refused with site_not_granted, which is the behavior to expect. The extension contains no remote code: every script it runs is packaged in it. Firefox: the source in the package is unminified and has no build step (JavaScript files are the sources).
